## Build decisions
- Chart drawn as hand-written SVG instead of Recharts (spec allows an equivalent): exact floating stacked steps, year band and "Target reached" marker; Recharts not installed.
- shadcn/ui not used: the only controls are chips, switches and one select, built with Tailwind.
- Gap bar drawn pink with white diagonal hatch and a darker outline, so it stays distinct from the pink Stores segments in the business view.
- "Target reached" shown as a black marker line with a tick at the running total, labelled on the axis.
- Dashed connectors join each bar to the next at the running total.
- Planned Scope 3 / Manufacturing shade #FDE3A6, planned Stores shade #FBCCD3 (lighter steps of the brand accents).
- A "Scroll sideways to see the whole roadmap →" hint appears when the chart is wider than its frame.
- Builder request 20 Nov 2026 (fix lane, UI polish): numbers shown in kt CO2 with one decimal (axis ticks without decimals); data and calculations stay in tonnes. Summary line adds % vs. base: Actual = Reductions/Base, Target = (Target−Base)/Base, Gap = −Gap/Base (when target reached: −beyond/Base); reductions negative, increases positive.
- Spec v1.2 (20 Nov 2026) promoted the Backlog's v1.1 change (span columns, Energy Efficiency rename, kt wording) into Remaining Work, together with the target slider.
- v1.2, builder request during checks (20 Nov 2026): Green Tariffs grouped too — added to the one-column list in spec v1.2 (still unmerged, so no version bump), CLAUDE.md, the data settings and checks D1, D3–D5, S5, S8.
- v1.2: span columns are flagged by the settings list `singleColumnMeasures`, not by the Excel; a one-column-list measure with a single year stays a normal bar.
- v1.2: the slider is a native range input (0–99, step 1) with an <output> showing "−50 %"; out-of-range values are clamped in roadmap.js. Summary percentages keep one decimal (v1.0 builder decision); the spec wording was corrected to match before the build.
- v2.0 (20 Nov 2026): the Backlog item "Adding/editing measures in the tool, saved for everyone" was promoted into Remaining work by spec v2.0 (Tier 2, Supabase, anyone with the link edits).
- v2.0: the chart reads real rows through the roadmap function from the start (no fixture-data phase): the short matrix (P1) allows reads through that function, and the data is the same public chart data; a later login comes with a new spec version.
- v2.0: all reads and writes go through Netlify Functions using PostgREST over fetch (no Supabase client library); the secret key is sent as the `apikey` header (plus Bearer only for a legacy eyJ key). SUPABASE_DATABASE_URL is read as the https project URL (fallback SUPABASE_URL); verify the names the extension writes on the first live build.
- v2.0: Save and Undo are two Postgres functions (apply_roadmap_save, undo_roadmap_save), SECURITY INVOKER, search_path '', execute for service_role only, serialised by an advisory lock; the function validates first, the table constraints are the backstop.
- v2.0: the panel stores unsaved edits as a draft in the browser; the chart preview uses only the draft lines that pass validation. Business chips and Scope 3 categories are derived from the rows, so a new business or category appears on its own (selected).
- v2.0: error text uses a dark pink #B3263C and error borders #D9485F (the brand defines no error colour; derived from the pink accent so it reads on white).
- v2.0: About this tool is a hash route (#about), no router library. Contact ghgroadmap@icloud.com (builder, 20 Nov 2026).
- v2.0: when the Supabase variables are missing, the functions' 503 reply names which variable NAMES are set and the kind of URL/key (never a value), so a missing extension connection is visible.
- Excel conversion is a Python script (scripts/convert_excel.py, needs openpyxl); documented in docs/data-conversion.md.
